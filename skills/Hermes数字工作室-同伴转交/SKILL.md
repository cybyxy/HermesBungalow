# Hermes数字工作室-同伴转交

## 概述

本技能定义 Hermes 数字工作室中 **Agent → 同伴** 的转交写法，与仓库内 `parseHermesBungalowInvokes` / `parseUserHandoffPrefix` 及后端 `@` 行解析一致：**仅识别独立成行的 `@` 手递**；历史 XML 转交格式已移除，不要使用。

---

## 触发条件


| 条件          | 说明                                        |
| ----------- | ----------------------------------------- |
| **多 Agent** | 场内 ≥2 名 Agent，且需要点名一名或多名同伴处理子任务。          |
| **用户意图**    | 用户要求接力、转交、@某人、@所有人、辩论/评审多轮等。              |
| **模型输出**    | 当前发言 Agent 在**本轮助手回复末尾**写出 handoff 行（见下）。 |


---

## 格式规则


| 规则        | 说明                                                                               |
| --------- | -------------------------------------------------------------------------------- |
| **一行一条**  | 每条 handoff **独占一行**，行首为 `@`。                                                     |
| **位置**    | 写在面向用户的**正文之后**；习惯放在**全文最后**，与系统注入的同伴提示一致。                                       |
| **token** | `@` 后为同伴的 **profile、游戏 id、姓名或显示名**；ASCII profile **不区分大小写**。token 内不含空格、竖线、@、换行。 |
| **竖线形式**  | `@token                                                                          |
| **无竖线形式** | `@token` 与说明之间**至少一个空格**；说明可含换行（与用户侧 `USER_AT_SPACE_RE`、助手侧 `AT_SPACE_LINE` 对齐）。 |
| **群发**    | `@所有人` 或 `@all`，可有/可无竖线；表示除**当前发言 Agent 自己**外，**其余同伴各收同一则 message**（由编排层展开）。     |
| **办公室走位** | **仅一对一**（本轮展开后恰好一名同伴）时，发起人会走近对方再回出生点。多目标（含 `@所有人`、或多行点名多人）时**发起人不移动**，各同伴推理并行触发。 |
| **对用户表述** | **禁止**称「多 Agent 已禁用」「不能调用其他 Agent」。Hermes 内置委派工具在 UI 关闭时，仍通过 **@-行** 完成同伴 relay。 |


---

## 是否需要对方回复


| 场景               | 建议                                   |
| ---------------- | ------------------------------------ |
| 需执行 + 汇报、多轮辩论/评审 | 在 message 中写清交付物，并明确「请回复本条」「完成后回复」等。 |
| 纯通知、并行广播         | 可不强制对方回复；避免处处加「请回复本条」。               |

## 模板（复制改写）

**单人（竖线）**

```text
（面向用户的正文……）

@对方的profile或id或姓名 | 交给对方的完整说明（背景、输入、期望输出、截止时间如有）。
```

**单人（无竖线）**

```text
（面向用户的正文……）

@对方的profile或id或姓名 交给对方的完整说明，写全需求与约束。
```

**群发**

```text
@所有人 | 同一说明：今日站会改到 15:00，请各自调整日历。
```

```text
@所有人 请看公告：仓库 main 冻结至发布完成，勿合入大改。
```

**多人、不同任务（多行）**

```text
@pymaster | 检查职业映射表与后端枚举是否一致，列出差异。
@uiwizard | 在设置页增加「职业」下拉与校验提示。
```

## 反例


| 不要                           | 原因                        |
| ---------------------------- | ------------------------- |
| `<hermes-bungalow-invoke …>` | 工程内已不再解析。                 |
| `@token` 与正文挤在同一段落中间、非行首     | 解析按**行**扫描，handoff 须单独成行。 |
| `@所有人` 后无正文                  | message 为空不会形成有效转交。       |
| 仅口头「请 pymaster 看下」而无 `@` 行   | 不会进入 relay 编排。            |


---

## 实现检查清单

- 每条 handoff 独占一行且以 `@` 开头。
- token 能解析到真实同伴（profile / id / 姓名 / display_name）。
- message 非空，说明完整，非空壳委派。
- 需要闭环时在正文中要求对方回复或交付物。
- 未向用户错误声称多 Agent 或委派能力不可用。
