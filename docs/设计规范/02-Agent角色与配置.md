## 1. Agent生成机制

### 1.1 Agent来源

**初始Agent**：游戏开始时只有主agent（城主）

**其他Agent**：通过用户配置Hermes Profile来生成。用户可以在Hermes系统中配置新的Agent Profile，配置完成后该Agent会出现在基地中。

### 1.2 Agent角色来源

Agent角色信息来自 **Hermes Profile 配置**（非硬编码）。每个Agent包含以下配置属性：

```yaml
agent:
  id: string              # 唯一标识符
  name: string            # 显示名称
  gender: string          # 性别：male / female（用户指定或random随机）
  role: string           # 职业类型
  personality: string    # 性格描述
  defaultWorkSpace: string # 默认工作房间
  avatar: string         # 头像资源路径（根据性别加载）
  pixelArt: string       # 像素立绘路径（根据性别加载）
  modelConfig: object    # 模型配置
  greetingStyle: string  # 打招呼风格
  catchphrase: string    # 口头禅
  memes: string[]        # 已解锁的梗
```

### 1.3 性别系统

**性别分配规则**：
- 用户创建新 Agent 时，可选择指定性别
- 用户未指定时，**系统随机分配**（male / female）
- 分配后不可更改

**素材加载规则**：
- 每个Agent有 **male（男性）** 和 **female（女性）** 两套独立素材
- 精灵图、头像等资源按性别分别配置
- 性别影响打招呼语气和部分行为表现

```yaml
# 性别分配示例
指定性别: gender: female  # 用户明确指定
随机分配: gender: random   # 用户未指定，系统随机
```

## 5. 社交机制

### 5.1 打招呼机制

> **说明**：以下机制与 PRD 保持一致。

#### 触发规则

| 要素 | 说明 |
|------|------|
| **触发场景** | 休息室、会议室、资料室、机房 |
| **触发条件** | Agent A 进入房间 → 遇到已在房间的 Agent B |
| **关系要求** | 关系值 ≥ 11（认识阶段） |
| **竞争关系** | 同职业Agent存在竞争，不触发打招呼 |
| **冷却时间** | 10分钟（同一对Agent在同地点） |
| **多Agent处理** | 如果房间已有多个Agent，与**最近的一个**打招呼 |
| **位置判断** | 同一房间即算相遇 |

#### 交互规则

- **一来一回**：Agent A 主动打招呼 → Agent B 回应 → 结束
- **状态互斥**：打招呼状态与协作交流状态互斥

#### 效果

| 属性 | 数值 | 上限 |
|------|------|------|
| 好感度 | +1~3 | 100 |
| 关系值 | +1 | 100 |

#### 打招呼内容分层

| 关系阶段 | 问候方式 |
|----------|----------|
| 认识 | 点头示意 |
| 朋友 | 友好问候 |
| 挚友 | 热情招呼 |

#### 关系上限

> 朋友 → 挚友（不允许恋人/办公室恋爱）

### 5.2 打招呼内容生成

> **说明**：打招呼内容由推理模型根据 Agent 的性格、职业、当前状态和关系阶段自动实时生成，无需配置固定内容。

**生成要素**：

| 要素 | 说明 |
|------|------|
| 性格 | 影响打招呼的语气和用词 |
| 职业 | 可能影响打招呼内容 |
| 关系阶段 | 认识/朋友/挚友决定问候方式 |
| 当前场景 | 休息室/会议室/资料室/机房 |
| 近期状态 | 刚完成任务/刚休息完/刚进门等 |

**生成示例**（仅供参考，实际由模型实时生成）：

```
认识阶段：简单点头/寒暄
- "你好。"
- "嗯，你好。"
- "来了啊。"

朋友阶段：友好问候/关心近况
- "嘿，今天怎么样？"
- "你好呀，在忙什么呢？"
- "哟！休息一下？"

挚友阶段：热情招呼/分享趣事
- "哇！你也在这儿！好久不见！"
- "嘿！今天气色不错嘛！"
- "来了来了！正好想找你聊聊！"
```

## 7. 技能详细规格

### 7.1 激励演说 (Motivate)

```yaml
技能名称: 激励演说
技能图标: 📣
解锁条件: 默认解锁（Lv.1）
冷却时间: 3秒
消耗: 无

效果:
  目标: 单个Agent
  效果类型:
    - 饱食度恢复 +30
    - 情绪值 +15
    - 社交需求 -10
  
使用场景:
  - Agent饱食度低于30%时
  - Agent情绪低落时
  - 重要任务前提升士气

使用限制:
  - 必须在同一房间或相邻房间
  - 目标Agent不能处于离线状态
```

**效果公式**：

```
饱食度恢复 = 30 × (1 + 0.1 × 城主等级)
情绪增加 = 15 × (1 + 0.05 × 关系紧密度)

关系紧密度修正（基于关系值）:
  陌生 (0-10):   ×0.8
  认识 (11-30):  ×1.0
  朋友 (31-70):  ×1.2
  挚友 (71-100): ×1.5
```

### 7.2 精准分配 (SmartAssign)

```yaml
技能名称: 精准分配
技能图标: 🎯
解锁条件: 城主Lv.2（累计XP 200）
冷却时间: 无（被动技能）
消耗: 无

效果:
  效果类型:
    - 任务匹配度判断准确率 +20%
    - 显示匹配度预测
    - 防止分配到不匹配的Agent
  
特殊显示:
  - 分配任务时显示推荐指数

使用场景:
  - 分配任何任务时自动生效
  - 帮助判断Agent与任务的匹配度
```

### 7.3 资源调度 (ResourceDispatch)

```yaml
技能名称: 资源调度
技能图标: 💰
解锁条件: 城主Lv.3（累计XP 500）
冷却时间: 5秒
消耗: 50城主积分

效果:
  目标: 单个Agent
  效果类型:
    - Token配额上限临时 +50%
    - 持续时间: 3秒
    - 效果结束后恢复正常上限
  
使用场景:
  - Agent电量即将耗尽但任务紧急
  - 高难度任务需要额外Token支持
  - 协作任务需要更多Token消耗
  
使用限制:
  - 每次只能调度一个Agent
  - 重复使用不叠加，取最大值
```

**效果公式**：

```
Token配额上限 = 基础上限 × (1 + 0.5 × 调度等级)
调度等级 = 城主积分消耗 / 50（向上取整）

示例:
  基础 Token 上限 = 1000
  消耗 50 积分 → 调度等级 1 → Token上限 = 1000 × 1.5 = 1500
  消耗 100 积分 → 调度等级 2 → Token上限 = 1000 × 2.0 = 2000
```

### 7.4 灵感赐予 (Inspire)

```yaml
技能名称: 灵感赐予
技能图标: 🔮
解锁条件: 城主Lv.4（累计XP 1000）
冷却时间: 7秒
消耗: 30城主积分

效果:
  目标: 协作中的Agent（2-3个）
  效果类型:
    - 协作任务质量 +15%
    - 有概率产出"灵感创意"（额外奖励）
    - 加速协作进度 10%
  
触发条件:
  - 必须在协作任务进行中
  - 目标Agent处于同一房间
  
使用场景:
  - 协作任务遇到瓶颈
  - 想要获得更好的协作成果
  - 关键项目需要突破
```

**暴击公式**：

```
灵感触发概率 = 15% × (1 + 0.05 × 城主等级)
协作质量加成 = 15% × (1 + 0.02 × 城主等级)
进度加速 = 10% × (1 + 0.01 × 城主等级)

示例（城主 Lv.4）:
  灵感触发概率 = 15% × 1.20 = 18%
  协作质量加成 = 15% × 1.08 = 16.2%
  进度加速 = 10% × 1.04 = 10.4%
```

```yaml
  - 只影响同一房间内的Agent
  - 不包括城主自己
  - 光环效果可以叠加但不明显
```

**效果公式**：

```
每个 Agent 情绪增加 = 10 × (1 + 0.1 × 房间内 Agent 数量修正)

房间内 Agent 数量修正:
  1 人: ×1.0
  2 人: ×1.1
  3 人: ×1.2
  4 人: ×1.3
  ≥5 人: ×1.5（上限）

示例: 房间内 3 个 Agent，光环效应
  每个人情绪增加 = 10 × 1.2 = +12（不是 +10）
```

### 7.6 全知视角 (OmniscientView)

```yaml
技能名称: 全知视角
技能图标: 👁️
解锁条件: 城主Lv.6（累计XP 5000）
冷却时间: 无（被动技能）
消耗: 无

效果:
  效果类型:
    - 可查看任意Agent详细状态
    - 可查看任意房间状态
    - 可查看任务详情和预测
    - 可查看其他Agent关系网络
  
特殊功能:
  - 无需进入房间即可查看
  - 显示隐藏信息（潜在风险、预测等）
  - 可标记重点关注对象
  
使用场景:
  - 任何时候均可使用
  - 制定策略时了解全局
  - 诊断团队问题
```

## 9. 技能冷却与公式

### 9.1 基础冷却公式

```
实际冷却时间 = 技能基础冷却 × 城主等级系数

城主等级系数:
  Lv.1: 1.0x（基础冷却）
  Lv.2: 0.9x
  Lv.3: 0.85x
  Lv.4: 0.8x
  Lv.5: 0.75x
  Lv.6: 0.7x
```

### 9.2 冷却重置机制

```
触发条件: 城主连续 3 次精准分配成功（匹配度 ≥ 90%）
效果: 随机重置 1 个技能的当前冷却
公式: cooldown[随机技能] = 0
```

### 9.3 冷却状态显示

```
状态 = "冷却中 (X/Y秒)"
进度条 = ████████░░░░░░░░ (当前进度/总冷却)

示例（激励演说，基础冷却3秒，城主Lv.3）:
  实际冷却 = 3 × 0.85 = 2.55秒 ≈ 3秒
  显示: "冷却中 (1/3秒)" → 1秒后 → "冷却中 (2/3秒)" → 1秒后 → "可用"
```

### 9.4 冷却状态追踪

```typescript
interface SkillCooldown {
  skillId: string;
  currentCooldown: number;  // 剩余秒数
  maxCooldown: number;      // 总冷却秒数
  isReady: boolean;          // 是否可用
  lastUsedAt?: number;      // 上次使用时间戳
}

interface SkillEffect {
  skillId: string;
  targetAgentId?: string;   // 目标Agent（可选）
  effectType: string;
  value: number;
  remainingTurns: number;   // 剩余秒
  startedAt: number;
}
```

## 10. 直接干预机制

城主对 Agent 的主动控制能力，体现"领袖权威"。

### 10.1 紧急任务（ForceTask）

```yaml
机制名称: 紧急任务
触发方式: 城主主动发起，无需 Agent 同意
效果: 强制中断 Agent 当前任务，立即执行新任务
优先级: P0（最高），无视冷却和难度

消耗:
  - 城主积分 -100
  - 目标 Agent 情绪 -20（被动接受的压力）

限制:
  - 每个游戏日最多使用 2 次
  - 不能同时对 2 个以上 Agent 发起

效果公示:
  "⚡ [Agent名] 被城主指派紧急任务：[任务名]，当前任务已中断"
```

### 10.2 房间调动（ForceMove）

```yaml
机制名称: 房间调动
触发方式: 城主选择 Agent + 目标房间
效果: Agent 立即移动到目标房间，原任务中断（如在房间内）

消耗:
  - 城主积分 -30
  - 目标 Agent 情绪 -5（被动调动的不满）

限制:
  - 调动后 Agent 需要 5 秒"重新聚焦"才能开始新任务
  - 协作中的 Agent 需要 10 秒（需要通知搭档）

特殊规则:
  - 不能调动正在执行 P0 紧急任务的 Agent
  - 不能调动处于"休息中"状态的 Agent
```

### 10.3 临时奖惩（TempReward/Penalty）

```yaml
机制名称: 临时奖惩
类型A - 表扬（TempPraise）:
  消耗: 城主积分 -20
  效果: 目标 Agent 情绪 +15，关系 +3
  触发: 即时生效，持续当前游戏日

类型B - 警告（TempWarning）:
  消耗: 无
  效果: 目标 Agent 情绪 -10，效率 -10%（当前任务）
  触发: 即时生效，持续 3 个任务

类型C - 暂停休息（ForceRest）:
  消耗: 城主积分 -50
  效果: Agent 强制进入休息，饱食度恢复 +40
  触发: 持续 1 小时游戏时间
  限制: 每个游戏日每个 Agent 只能使用 1 次
```
