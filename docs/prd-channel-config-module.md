## 1. 背景与目标

### 1.1 背景

Hermes Agent 平台支持多 Channel（渠道）接入——如 Console、Discord、Telegram、飞书等。现有配置方式以 YAML 文件和命令行操作为主，缺乏图形化统一管理入口。用户（尤其是非技术背景的管理员）难以直观地查看、新增、编辑、启禁用各 Channel 的状态。

### 1.2 目标

在现有 Web 图形化界面中，**以电话图标为入口**，一键调起 Channel 配置面板，实现：

- 可视化配置所有 Channel 的参数
- 实时查看各 Channel 连接状态
- 启禁用、编辑、新增、删除 Channel
- 配置变更即时生效，无需重启服务

## 3. 功能规格

### 3.1 入口：电话图标

- **位置**：Web UI 顶栏或侧边栏（需与 UI 设计确认）
- **图标样式**：📞 或自定义电话 icon
- **交互**：
  - 点击 → 打开 Channel 配置面板（右侧抽屉 Drawer，默认宽度 480px）
  - 面板右上角有关闭按钮（×）
  - 点击遮罩层也可关闭

### 3.2 Channel 配置面板

#### 3.2.1 整体布局

```
┌─────────────────────────────────────┐
│  Channel 配置              [×]      │
├─────────────────────────────────────┤
│  [搜索框]              [+ 新增]      │
├─────────────────────────────────────┤
│  ┌─────────────────────────────┐    │
│  │ 🔵 Console      [在线]  [⚙️] │    │
│  │    endpoint: ws://...       │    │
│  └─────────────────────────────┘    │
│  ┌─────────────────────────────┐    │
│  │ 🟢 Discord     [在线]  [⚙️] │    │
│  │    guild: xxx-bot           │    │
│  └─────────────────────────────┘    │
│  ┌─────────────────────────────┐    │
│  │ 🔴 飞书          [离线]  [⚙️] │    │
│  │    error: auth failed       │    │
│  └─────────────────────────────┘    │
└─────────────────────────────────────┘
```

#### 3.2.2 Channel 列表项

每个 Channel 显示：
- **图标/颜色**：标识 Channel 类型
- **名称**：用户定义的 Channel 名称
- **状态标签**：`在线`（绿）/ `离线`（灰）/ `错误`（红）
- **简短摘要**：如 endpoint、bot name 等关键信息
- **操作按钮**：配置（⚙️）、启禁用（开/关 toggle）

#### 3.2.3 新增 / 编辑 Channel 弹窗

点击「新增」或列表项「⚙️」，弹出配置表单：

```
┌─────────────────────────────────────┐
│  新增 Channel                 [×]   │
├─────────────────────────────────────┤
│  Channel 类型  [下拉选择 ▼]         │
│                                      │
│  名称         [________________]     │
│                                      │
│  === 根据类型动态渲染以下字段 ===    │
│                                      │
│  [字段1]     [________________]     │
│  [字段2]     [________________]     │
│  [密码/密钥]  [________________]     │
│                                      │
│  [取消]              [保存]         │
└─────────────────────────────────────┘
```

**Channel 类型及对应字段：**

| Channel 类型 | 必填字段 |
|-------------|---------|
| Console | endpoint (WebSocket URL), port |
| Discord | bot_token, guild_id |
| Telegram | bot_token, api_base_url |
| 飞书 | app_id, app_secret, bot_name |
| Slack | bot_token, signing_secret |
| WebSocket | ws_url, auth_type |

#### 3.2.4 启禁用逻辑

- 每个 Channel 右侧有一个 Toggle Switch
- 关闭后：
  - 状态变为「已停用」（灰色标签）
  - 后端停止该 Channel 的连接/监听
  - 列表项灰度显示
- 启用时：校验必填字段，完整则启动连接

#### 3.2.5 删除确认

点击删除 → 二次确认弹窗：
```
确认删除 Channel「飞书」吗？此操作不可撤销。
              [取消]  [确认删除]
```

## 4. 技术规格

### 4.1 前端

- **框架**：React + TypeScript（若项目已有前端技术栈则沿用）
- **UI 组件库**：Ant Design 或 shadcn/ui
- **状态管理**：React Context / Zustand
- **HTTP 客户端**：axios
- **实时状态**：WebSocket 或轮询（每 10s 拉取一次 Channel 状态）

### 4.2 后端

- **现有架构**：保持一致（Python FastAPI 或其他）
- **API 设计**：

| 方法 | 路径 | 描述 |
|------|------|------|
| GET | `/api/channels` | 获取所有 Channel 配置列表 |
| GET | `/api/channels/{id}` | 获取单个 Channel 详情 |
| POST | `/api/channels` | 新增 Channel |
| PUT | `/api/channels/{id}` | 更新 Channel 配置 |
| DELETE | `/api/channels/{id}` | 删除 Channel |
| POST | `/api/channels/{id}/enable` | 启用 Channel |
| POST | `/api/channels/{id}/disable` | 停用 Channel |
| GET | `/api/channels/status` | 批量获取 Channel 连接状态 |

### 4.3 数据模型

```python
class Channel:
    id: str               # UUID
    name: str             # 用户定义的名称
    type: str             # console | discord | telegram | feishu | slack | websocket
    enabled: bool         # 是否启用
    config: dict          # 类型相关的配置（敏感字段加密存储）
    status: str            # online | offline | error
    error_message: str | None
    created_at: datetime
    updated_at: datetime
```

### 4.4 安全考虑

- **敏感信息**：Channel 的 token、secret 等存储时加密（如使用 AES 或 vault）
- **前端展示**：密码/密钥字段显示为 `***`，不可见明文
- **权限控制**：仅管理员角色可操作 Channel 配置（预留 RBAC 扩展）

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| **性能** | Channel 列表加载 < 500ms；状态刷新无感知 |
| **可用性** | 配置错误时给出明确提示，不允许保存无效配置 |
| **容错** | 单个 Channel 连接失败不影响其他 Channel |
| **日志** | Channel 启禁用、配置变更需记录操作日志 |
| **可访问性** | 符合 WCAG 2.1 AA 标准（键盘导航、屏幕阅读器支持） |
