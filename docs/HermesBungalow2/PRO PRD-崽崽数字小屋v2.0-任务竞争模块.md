# 任务竞争模块 · PRD v2.0

> 版本：v2.0 | 状态：已归档 | 作者：顾言卿 | 日期：2026-05-03

---

## 1. 概述

### 1.1 模块目标
在多人抢任务场景下，通过公平抽签决定任务归属，避免关系值歧视，激发 Agent 主动竞争。

### 1.2 触发条件

| 条件 | 说明 |
|------|------|
| 任务人数 | 只需要 1 人 |
| 空闲人数 | 同职业 ≥ 2 名空闲 Agent |
| 举手数量 | 多个 Agent 同时举手 |

**三者同时满足时，触发竞争抽签流程。**

---

## 2. 竞争机制

### 2.1 抽签规则

```
竞争方式：纯公平抽签（无加权）
```

- 所有举手 Agent 拥有**等概率**中签机会
- 不考虑关系值、职业等级、历史完成任务数
- 城主**不可干预**，只能旁观

---

## 3. 奖惩设计

### 3.1 奖惩数值表

| 结果 | 奖励/惩罚 | 数值范围 |
|------|-----------|----------|
| **中签（抢到）** | 积分奖励 | +8 ~ +15 |
| **未中签（没抢到）** | 积分扣除 + 关系损伤 | -5 ~ -10 积分，-3 ~ -5 关系值 |
| **加倍惩罚**（触发条件见 3.2） | 积分大幅扣除 | -30 ~ -50 积分 |

### 3.2 加倍惩罚触发条件

```
触发条件：连续竞争失败 ≥ 3 次（跨任务累加）
```

- 连续失败计数**跨任务累加**，失败次数不清零
- 触发加倍惩罚后，计数器**不清零**，继续累加
-城主干预权：不可干预，只能旁观

---

## 4. 流程设计

### 4.1 完整流程

```
[任务发布]
    ↓
[检测触发条件] → 不满足 → 正常分配
    ↓ 满足
[竞争公示] → 显示：任务名、参与 Agent、抽签倒计时
    ↓
[抽签动画] → 3秒动画展示抽签过程（固定时长，不可配置）
    ↓
[结果公示] → 中签者高亮 + 未中签者灰色
    ↓
[积分结算] → 按奖惩表执行
    ↓
[竞争记录存档] → event_log 记录，供成就系统调用
```

### 4.2 竞争公示 UI

```
┌─────────────────────────────────────┐
│ ⚡ 任务竞争！                       │
│ ─────────────────────────────────── │
│ 任务：修复验证码失效问题            │
│ 奖励：中签 +8~15分                  │
│ 惩罚：未中 -5~-10分，关系-3~-5     │
│ ─────────────────────────────────── │
│ 参与抽签：                          │
│   👤 阿猿（程序员） 举手            │
│   👤 小美（设计师） 举手            │
│   👤 点点（测试员） 举手            │
│ ─────────────────────────────────── │
│        [抽签中... 3s]               │
└─────────────────────────────────────┘
```

## 5. 数值模型

### 5.1 奖励随机范围

```
中签奖励 = random(8, 15)
未中积分惩罚 = random(-5, -10)
未中关系惩罚 = random(-3, -5)
加倍惩罚 = random(-30, -50)
```

### 5.2 连续失败计数

| 参数 | 值 | 说明 |
|------|-----|------|
| 加倍惩罚触发阈值 | ≥ 3 次 | 连续失败跨任务累加 |
| 计数器重置 | 不重置 | 保持惩罚压力 |
| 触发后计数器 | 继续累加 | 不清零 |

---

## 6. 交互说明

### 6.1 Agent 举手逻辑

- Agent 检测到自己满足任务要求时，**自动举手**（无需用户操作）
- 举手后，该 Agent 在任务卡上显示"🤚 竞争中"
- 抽签结束后，未中签 Agent 自动放下手

### 6.2 城主视角

- 城主只能旁观，不能干预抽签结果
- 可查看历史竞争记录（event_log）
- 可查看各 Agent 竞争统计（胜率、连败次数）

## 7. 技术建议

| 项目 | 建议 |
|------|------|
| 前端 | 抽签动画使用 Phaser 粒子效果，固定 3 秒 |
| 后端 | 抽签使用 `random` 模块，种子基于区块高度防伪 |
| 存储 | 竞争记录写入 `event_log`，类型 `task_lottery` |
