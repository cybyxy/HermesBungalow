## 1. 概述

### 1.1 模块目标

设计崽崽数字小屋完整的任务系统，支撑单人任务、协作任务、竞争任务三种模式，与 2.0 新增的竞争模块无缝衔接。

### 1.2 现有系统能力

**Task 模型**（`backend/api/game/models.py`）：

```python
@dataclass
class Task:
    id: int
    name: str
    description: str = ""
    progress: float = 0.0
    status: str = "pending"          # pending | in_progress | completed
    assignee_id: str | None = None
    required_profession: str = "程序员"
    difficulty: int = 2               # 1-5
    reward: int = 100
    quality: int = 0
    estimated_hours: float = 2.0
    is_collaborative: bool = False   # 协作任务标记
    collaboration_bonus: float = 0.3  # 协作加成系数
    subtasks: list[dict] = field(default_factory=list)
```

## 2. 任务类型分类

| 类型 | 触发条件 | 分配方式 | 竞争 |
|------|----------|----------|------|
| **单人任务** | 普通任务，只需 1 人 | 城主指派 / 自动分配 | 无 |
| **协作任务** | `is_collaborative=True`，需多人 | 城主指派多人 | 无 |
| **竞争任务** | 同职业≥2 空闲 Agent 举手 | 抽签决定 | 有 |

## 3. 任务流程设计

### 3.1 单人任务流程

```
[任务发布]
    ↓
[检测职业匹配 Agent]
    ↓ 有匹配？
    ├─ 有 → 指派给最优 Agent（关系值/能量/专注度综合评分）
    └─ 无 → 提示城主：无可用 Agent
    ↓
[任务开始] → Agent 状态变为 working
    ↓
[任务进行中] → 城主可查看进度
    ↓
[任务完成] → 结算奖励 + 更新 Agent 状态
```

### 3.2 协作任务流程

```
[协作任务发布]
    ↓
[城主指派 N 名 Agent]（职业互补有额外质量加成）
    ↓
[子任务拆分] → 自动按人数拆分子任务
    ↓
[并行执行] → 各 Agent 独立执行子任务
    ↓
[汇总验收] → 所有子任务完成 → 触发协作奖励结算
    ↓
[奖励发放] → 基础奖励 × 协作加成 × 关系值系数
```

### 3.3 竞争任务流程（与竞争模块衔接）

```
[任务发布]
    ↓
[检测竞争触发条件]
    ├─ 条件不满足 → 进入单人/协作流程
    └─ 条件满足（单人任务 + 同职业≥2空闲 + 多人举手）
    ↓
[触发 competition.py]
    ├─ run_lottery()         ← 抽签选赢家
    ├─ resolve_competition() ← 奖惩计算
    └─ _broadcast()          ← WebSocket 广播
    ↓
[竞争公示 + 3秒动画]
    ↓
[结果落地] → 更新 task.assignee_id + event_log
```

## 4. 任务分配算法

### 4.1 单人任务分配评分

```python
def score_agent(agent: Agent, task: Task) -> float:
    # 基础分：能量充足给高分
    energy_score = agent.energy / 100

    # 专注度：working 时扣分
    focus_score = agent.focus / 100 if agent.status == "idle" else 0.5

    # 职业匹配：完全匹配给 1.0，无关给 0.3
    profession_score = 1.0 if agent.profession == task.required_profession else 0.3

    # 关系值加成（≤10%）
    relation_bonus = min(agent.relation / 1000, 0.1)

    return energy_score * 0.3 + focus_score * 0.2 + profession_score * 0.4 + relation_bonus
```

### 4.2 协作任务职业加成

| 组合 | 质量加成 |
|------|----------|
| 程序 × 设计 | +20% |
| 程序 × 测试 | +15% |
| 设计 × 产品 | +15% |
| 三职业协作 | +30% |

### 4.3 竞争任务分配

**见竞争模块 PRD**，核心是 `secrets.randbelow` 纯随机抽签。

## 6. 奖惩体系

### 6.1 单人任务奖励

```
基础奖励 = task.reward
完成质量系数 = 0.8 + (task.quality / 100) * 0.4   # 0.8~1.2
最终奖励 = floor(基础奖励 × 完成质量系数)
```

### 6.2 协作任务奖励

```
基础奖励 = task.reward
协作加成 = 1 + task.collaboration_bonus              # 1.0~1.3
职业互补加成（满足条件时）= 额外 ×1.15~1.30
关系值系数 = 1 + min(平均关系值/1000, 0.1)          # ≤1.1
最终奖励 = floor(基础奖励 × 协作加成 × 职业互补加成 × 关系值系数)
```

### 6.3 竞争任务奖惩

| 结果 | 数值 |
|------|------|
| 中签奖励 | +8 ~ +15 分 |
| 未中积分 | -5 ~ -10 分 |
| 未中关系 | -3 ~ -5 |
| 加倍惩罚（≥3连败） | -30 ~ -50 分 |

**（详细数值见 PRD v2.0 奖惩设计节）**

## 8. 待确认项

| 序号 | 待确认项 | 决策方 | 决策结果 |
|------|----------|--------|----------|
| 1 | 协作任务最小人数（2人起还是3人起） | 城主 | **2人起** |
| 2 | 任务超时机制（Agent 消极工作是否扣除奖励） | 城主 | **是**，超时扣除50%奖励 |
| 3 | 任务可拒绝吗？（Agent 能量不足时是否可拒绝任务） | 城主 | **可以**，但能量<20%时才能拒绝，拒绝扣关系值-5 |
| 4 | 竞争任务公示期间，Agent 可以取消举手吗 | 技术侧 | **不可以**，举手后不可撤销，公示期结束前必须参与抽签 |

## 9. 城主决策纪要（2026-05-04）

- 协作任务从**2人起**，鼓励小规模协作
- 任务超时扣除**50%奖励**，避免消极磨工
- 能量<20%时可拒绝任务，**拒绝扣关系值-5**，避免滥用
- 竞争举手**不可撤销**，保证抽签公平性
