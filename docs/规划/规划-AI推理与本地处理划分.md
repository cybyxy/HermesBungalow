# Hermes数字工作室 — AI推理与本地处理划分

> **文档版本**：v1.0
> **目的**：明确区分哪些功能需要AI推理，哪些只需本地程序处理
> **原则**：AI推理成本高，应尽量减少调用；本地程序处理效率高

---

## 一、核心原则

| 原则 | 说明 |
|------|------|
| **AI推理成本高** | 每次调用消耗Token，有延迟 |
| **本地处理效率高** | 毫秒级响应，无成本 |
| **混合模式** | AI处理创意/判断，本地处理数值/状态 |
| **尽量减少AI调用** | 能本地处理的绝不用AI |

---

## 二、功能划分总览

```
Hermes数字工作室
│
├── 🤖 需要AI推理（LLM调用）
│   ├── 对话内容生成
│   ├── Agent决策判断
│   ├── 任务复杂度分析
│   ├── 行为推理

│
└── 💻 本地程序处理
    ├── 数值计算
    ├── 状态机转换
    ├── 计时器/冷却
    ├── 碰撞/移动
    ├── 随机数生成
    ├── UI渲染
    └── 数据存储
```

## 三、详细划分

### 3.1 社交系统

#### 需要AI推理

| 功能 | 原因 | 调用频率 |
|------|------|----------|
| **打招呼内容生成** | 根据性格、职业、关系阶段、场景实时生成不同内容 | 每次打招呼（可缓存模板） |
| **打招呼语气判断** | 关系阶段不同，语气不同（冷淡/友好/热情） | 每次打招呼 |
| **闲聊内容生成** | 基于Agent性格和当前状态生成对话 | 每次闲聊 |
| **协作交流内容生成** | 根据任务类型、进度、困难实时生成 | **按需调用，不限制频率** |
| **分享零食AI判断** | 判断是否分享（基于性格+关系+情境） | 每次购买零食后 |
| **深度交流话题生成** | 生成有意义的对话内容 | 每次深度交流 |

#### 本地程序处理

| 功能 | 处理方式 |
|------|----------|
| 打招呼触发检测 | 房间碰撞检测 + 冷却时间检查 |
| 关系值增减 | 固定数值运算 |
| 好感度增减 | 固定数值运算 |
| 社交需求增减 | 固定数值运算 |
| 关系阶段判断 | 阈值比较（0-10/11-30/31-70/71-100） |
| 分享概率计算 | 固定概率（30%/60%）随机判定 |
| 社交冷却计时 | 本地定时器 |

#### 缓存策略（减少AI调用）

```
打招呼内容 → 本地模板 + 少量变量替换
           → 相同关系阶段的模板可复用
           → AI只生成关键变量（名字/职业）

协作交流 → 按需调用AI，正常时用本地模板过渡
         → 城主可监听/参与
```

### 3.2 任务系统

#### 需要AI推理

| 功能 | 原因 | 调用频率 |
|------|------|----------|
| **任务复杂度分析** | 判断任务需要多少人、什么职业 | 每次新任务 |
| **是否需要协作判断** | 分析任务是否涉及多职业/高难度 | 每次新任务 |
| **协作任务分配** | 根据Agent状态分配任务角色 | 每次协作任务 |
| **职业匹配度评估** | 判断Agent能力与任务匹配程度 | 每次任务分配 |
| **任务完成质量评价** | AI判断任务完成好坏 | 每次任务完成 |

#### 本地程序处理

| 功能 | 处理方式 |
|------|----------|
| 任务队列管理 | 队列数据结构（FIFO） |
| 任务状态转换 | 状态机（pending → in_progress → completed/failed） |
| 任务计时 | 本地定时器 |
| 任务进度更新 | 固定百分比递增 |
| XP/积分计算 | 固定公式运算 |
| 任务超时检测 | 本地计时器 |
| 竞争抽签 | 随机数（Math.random） |
| 竞争者举手判断 | 固定条件检测 |

#### 任务竞争流程划分

```
用户提交任务
    ↓
【本地】主agent接收任务
    ↓
【AI推理】任务复杂度分析 → 需要几个人？什么职业？
    ↓
【本地】检查是否有同职业多人竞争
    ↓
如果竞争：
    【本地】随机抽签（Math.random）
    ↓
【AI推理】向获选Agent发送任务描述
    ↓
【本地】更新任务状态、计时
    ↓
【本地】任务完成 → 触发奖励计算
    ↓
【AI推理】任务质量评价（可选）
```

## 四、AI推理调用频率控制（重要！）

> **核心考量**：AI推理消耗Token，成本高，必须严格控制调用频率
> **优化原则**：能用本地解决的不调用AI，能合并的不分散调用

### 4.1 调用频率分级

| 级别 | 调用频率 | 场景 | 优化方式 |
|------|---------|------|----------|
| **独立任务** | 无限制 | 单个Agent独立工作 | 正常AI推理 |
| **协作交流** | 按需调用 | 需要对话时 | 城主可监听 |
| **行为决策** | 本地优先 | 多Agent场景 | 规则判断，异常才AI |
| **城主技能/事件** | 按需调用 | 必要时 | 正常使用 |

### 4.2 协作交流优化方案

**按需调用，不限制频率**

```
【协作交流 - 原则】
✅ 需要对话时调用AI（如：遇到问题需要讨论）
✅ 正常协作时使用本地模板过渡
✅ 城主可以选择监听/参与协作交流
✅ 不人为限制AI调用次数，保证协作质量
```

**何时使用本地模板**：
```
【本地模板 - 正常协作过渡】
├── "正在设计中..." / "写代码中..." / "测试中..."
├── "进度 30% / 60% / 90%"
├── "这块我来负责..."
└── "你那边怎么样了？"

【需要AI对话时】
├── 遇到问题需要讨论 → AI生成讨论内容
├── 任务有进展需要同步 → AI生成同步内容
├── 需要做决策 → AI生成选项分析
└── 城主参与 → AI生成城主互动内容
```

**城主参与模式**：
```
【监听模式】
城主选择监听 → AI生成协作对话内容供城主查看
城主可随时打断参与

【不监听模式】
本地模板显示状态 → 不调用AI生成对话内容
节省token消耗
```

### 4.3 单个Agent独立任务

**单个Agent独立任务时AI推理不受限制**

```
【独立任务 - 无频率限制】
├── Agent独立工作 → 正常AI推理
├── 工作过程中 → AI判断下一步
├── 遇到问题 → AI分析原因
├── 需要决策 → AI给出选项
└── 任务完成 → AI生成总结

【原因】
单个Agent独立工作，不会产生多Agent的token叠加问题
每分钟1次AI调用 = 60次/小时 = 正常消耗水平
```

### 4.4 Agent自主决策优化方案

**问题**：多个Agent每30秒检测一次，累积token消耗巨大

**优化方案**：**本地规则判断**为主，AI仅判断异常情况

```
【Agent自主决策 - 优化前】
❌ 每个Agent每30秒调用1次AI判断
❌ 5个Agent = 每30秒5次AI调用
❌ 1小时 = 600次AI调用

【Agent自主决策 - 优化后】
✅ 本地规则判断：能量<50？专注力<60？社交需求>70？
✅ 规则判断命中率：90%的情况不需要AI
✅ 仅当本地规则无法判断时（如："最近情绪有点低落"）
✅ AI调用频率：每个Agent约1次/小时（降低90%）
```

**本地规则判断示例**：

```
【本地可完全处理的判断】
├── 能量 < 50 → 需要进食/休息
├── 能量 < 30 → 需要紧急休息
├── 专注力 < 60 → 需要咖啡/休息
├── 社交需求 > 70 → 需要社交
├── 睡意 > 80 → 需要睡眠
└── 以上情况 → 直接执行对应行为

【需要AI判断的情况 - 极少】
├── 能量和专注力都中等，但效率下降 → 判断原因
├── 社交需求不高，但情绪持续低落 → 判断原因
├── 多个需求同时不满 → 优先级判断
└── 其他复杂情境 → "最近状态不太好"等主观感受
```

### 4.5 缓存策略

```
【可缓存 - 一次生成，多次使用】
├── 打招呼模板（按关系阶段：认识/朋友/挚友）
│   └── 认识："你好。" / 朋友："最近怎么样？" / 挚友："嘿！好久不见！"
├── 职业梗/口头禅
│   └── 设计师："这个颜色..." / 程序员："命名规范..."
├── 闲聊开场白（按性格分类）
│   └── 开朗："今天天气真好" / 内向："嗯..."
└── 协作状态描述模板
    └── "正在设计中..." / "写代码中..." / "测试中..."

【必须实时生成的 - 严格控制】
├── 任务具体内容（每个任务不同）
├── 协作中的具体讨论（任务相关）
├── 事件响应策略（每个事件不同）
└── 城主激励/点评（每次不同）
```

### 4.6 多Agent合并调用

```
【问题】
每个Agent独立调用AI，token消耗 = Agent数量 × 单次调用

【优化方案】
主agent作为协调者，统一收集多个Agent的问题
合并为一次AI调用返回多个响应

【示例】
❌ 优化前：设计师问"我该做什么？"→ AI调用1次
❌ 优化前：程序员问"我该做什么？"→ AI调用1次
❌ 优化前：测试员问"我该做什么？"→ AI调用1次
    = 3次AI调用

✅ 优化后：3个Agent同时询问 → 主agent合并为1次调用
✅ 返回：[{Agent: "设计师", task: "..."}, {...}, {...}]
    = 1次AI调用
```

### 4.7 频率控制总结

| 功能 | 调用方式 | 优化说明 |
|------|----------|----------|
| **协作交流** | 按需调用AI | 遇到问题/需要讨论时调用，正常用本地模板 |
| **Agent独立任务** | 无频率限制 | 单个Agent正常工作，正常AI推理 |
| **Agent行为决策** | 本地规则优先 | 规则判断90%，异常情况才用AI |
| **打招呼内容** | 模板缓存 | 本地模板+变量，不实时生成 |
| **多Agent询问** | 合并为1次 | 主agent统一收集，减少N-1次调用 |

## 四、用户输入触发AI推理机制

> **强制要求**：用户每一次在输入框输入内容，都必须触发AI推理，并更新所有对应的文档。

### 4.1 触发规则

```
┌─────────────────────────────────────────────────────────────┐
│  用户输入框                                                  │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  普通输入（无@指定）                                          │
│       ↓                                                      │
│  主agent（Hermes）AI推理                                        │
│       ↓                                                      │
│  更新所有相关文档                                             │
│                                                              │
│  ─────────────────────────────────────────────────────────  │
│                                                              │
│  指定输入（@某个Agent）                                       │
│       ↓                                                      │
│  目标Agent AI推理                                            │
│       ↓                                                      │
│  更新该Agent相关文档                                          │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 触发流程

```
用户输入
   │
   ├── 普通输入
   │     │
   │     └── 主agent AI推理调用
   │              │
   │              ├─【1. 意图解析】
   │              │    ├─ 识别用户意图（命令/对话/询问/干预）
   │              │    ├─ 识别涉及的目标Agent列表
   │              │    └─ 识别涉及的任务/事件/场景
   │              │
   │              ├─【2. 状态更新】
   │              │    ├─ 数值变化（能量/专注力/社交/情绪/睡意）
   │              │    ├─ 任务状态变化（创建/分配/完成/失败）
   │              │    ├─ 位置变化（如有移动指令）
   │              │    └─ 社交关系变化（如有互动）
   │              │
   │              ├─【3. 事件触发检查】
   │              │    ├─ 检查是否有事件被触发
   │              │    ├─ 检查是否有成就解锁
   │              │    └─ 检查是否有里程碑达成
   │              │
   │              ├─【4. 文档更新】← 必须执行
   │              │    ├─ PRD完整版
   │              │    ├─ 相关子系统文档（任务/社交/数值等）
   │              │    └─ 涉及的Agent专属文档
   │              │
   │              ├─【5. 前端推送】← 必须推送
   │              │    ├─ agent:update（Agent状态变更）
   │              │    ├─ task:update（任务状态变更）
   │              │    └─ notification（如有需要提醒的内容）
   │              │
   │              └─【6. 响应生成】
   │                   ├─ 生成主agent回复内容（如有）
   │                   └─ 生成相关Agent响应内容（如有）
   │
   └── @指定输入
         │
         └── 目标Agent AI推理调用
                  │
                  ├─【1. 意图解析】
                  │    ├─ 识别用户对目标Agent的具体指令/对话
                  │    └─ 识别涉及的上下文（任务/社交/场景）
                  │
                  ├─【2. 状态更新】
                  │    ├─ 该Agent数值变化
                  │    ├─ 该Agent任务状态变化
                  │    ├─ 该Agent位置变化（如有）
                  │    └─ 该Agent社交关系变化
                  │
                  ├─【3. 文档更新】← 必须执行
                  │    ├─ PRD完整版
                  │    ├─ 任务系统文档（如有涉及）
                  │    ├─ 社交系统文档（如有涉及）
                  │    └─ 该Agent专属文档
                  │
                  ├─【4. 前端推送】← 必须推送
                  │    ├─ agent:update（该Agent状态）
                  │    └─ notification（如有）
                  │
                  └─【5. 响应生成】
                       ├─ 生成该Agent回复内容
                       └─ 通知主agent（如有联动）

### 4.3 更新范围

| 输入类型 | 更新文档 |
|---------|---------|
| **普通输入** | PRD完整版 + 所有相关子系统文档 |
| **@指定Agent** | PRD完整版 + 该Agent专属文档 |

### 4.4 AI推理内容（每次输入必执行）

每次用户输入触发AI推理时，必须完成以下推理：

```
1. 【意图识别】
   - 用户想说什么/做什么？
   - 目标是谁（主agent还是指定agent）？

2. 【状态更新】
   - 相关Agent数值变化（能量/专注力/社交/情绪/睡意）
   - 任务状态变化（如有）

3. 【社交影响】
   - 关系值/好感度变化
   - 关系阶段判断

4. 【后续建议】
   - 是否需要提醒用户某些事项
   - 是否需要生成Agent响应内容
```

### 4.5 实现约束

```typescript
// 前端输入框 - 伪代码
input.on('change', async (text) => {
  // 1. 解析输入
  const target = text.startsWith('@') ? parseAgent(text) : '主agent';

  // 2. 调用后端推理接口
  await api.post('/ai/reason', {
    input: text,
    target: target,  // '主agent' 或 'Agent_ID'
    timestamp: Date.now()
  });

  // 3. 后端必须：
  //    - 执行完整AI推理
  //    - 更新所有相关文档
  //    - 返回更新后的状态
});

// 禁止行为 ❌
input.on('change', (text) => {
  // 禁止：不做AI推理直接更新状态
  // 禁止：跳过某些文档的更新
  // 禁止：只更新数值不更新文档
});
```

## 五、技术实现建议

### 5.1 本地处理优先原则

```
所有游戏逻辑优先本地处理：
1. 数值计算 → 本地固定公式
2. 状态检测 → 本地条件判断
3. 动画播放 → 本地渲染
4. 数据存储 → 本地持久化

只有以下情况才调用AI：
1. 需要生成文本内容
2. 需要复杂判断（超过固定规则）
3. 需要创意生成
```

### 5.2 AI调用时机

```
【适合AI调用】
✓ 用户发起对话
✓ 重要剧情/事件
✓ 任务分配决策
✓ 复盘/点评内容

【不适合AI调用】
✗ 数值增减
✗ 冷却检测
✗ 状态转换
✗ 路径计算
```

### 5.3 降级策略

```
AI服务不可用时：
1. 使用本地预设回复模板
2. 简化判断逻辑为固定规则
3. 延迟非关键AI功能
4. 保持核心游戏逻辑正常运行
```

## 七、总结

### AI推理原则
- **单个Agent独立任务**：无频率限制，正常AI推理
- **协作交流**：按需调用AI，不限制频率城主可监听
- **打招呼/状态显示**：本地模板，不调用AI
- **多Agent同时询问**：合并为1次调用

### 本地处理职责（多数）
- **数值运算**：所有属性变化
- **状态管理**：任务、Agent、设施
- **计时控制**：冷却、持续、间隔
- **随机事件**：抽签、概率
- **渲染动画**：移动、表情、UI
- **数据存储**：存档、状态持久化

> **核心思想**：AI是大脑（做决策），本地是身体（执行动作）
