# Hermes数字工作室 — 前后端职责划分

> **文档版本**：v1.0
> **核心原则**：业务逻辑在后端，前端只做展示
> **通信方式**：WebSocket（实时推送）+ HTTP REST（查询）
> **状态管理**：后端是唯一事实来源（Single Source of Truth）

---

## 一、核心原则

```
┌─────────────────────────────────────────────────────────────────────┐
│                           架构原则                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   【后端 - 游戏框架】                【前端 - 展示层】                │
│   ├── 业务逻辑（100%）             ├── UI渲染（100%）               │
│   ├── 状态管理（唯一事实来源）      ├── 动画播放                    │
│   ├── 数值计算                      ├── 用户输入捕获                │
│   ├── AI推理调用                    └── 音视频播放                  │
│   ├── 任务调度                                                              │
│   ├── 事件系统                      【禁止前端做的】                 │
│   ├── 碰撞检测                      ├── 业务逻辑判断                │
│   ├── 路径规划                      ├── 状态计算                    │
│   └── 数据存储                      ├── AI推理                      │
│                                   └── 任务分配                      │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 二、后端职责（游戏框架）

### 2.1 核心游戏状态（后端唯一管理）

```python
# 后端管理的核心状态
GameState:
├── agents: Dict[agent_id, AgentState]      # 所有Agent状态
├── rooms: Dict[room_id, RoomState]          # 所有房间状态
├── tasks: Dict[task_id, TaskState]          # 所有任务状态
├── city_lord: CityLordState                # 城主状态
├── social_graph: SocialGraph                # 社交关系图
├── event_queue: EventQueue                  # 事件队列
└── time: GameTime                          # 游戏时间
```

### 2.2 业务逻辑模块

| 模块 | 后端职责 |
|------|----------|
| **Agent管理** | 创建/删除/状态变更/属性计算 |
| **数值系统** | 能量/专注力/社交/情绪/睡意的消耗与恢复 |
| **任务系统** | 任务生成/分配/执行/完成/评价 |
| **竞争系统** | 举手检测/抽签/结果计算/惩罚 |
| **社交系统** | 打招呼/协作交流/深度社交/分享零食 |
| **关系系统** | 关系值计算/阶段判断/好感度 |
| **事件系统** | 事件触发/响应/后果处理 |
| **城主技能** | 技能效果计算/冷却管理/解锁判断 |
| **成长系统** | XP计算/升级判定/技能点分配 |
| **碰撞检测** | Agent间碰撞/房间边界/设施使用 |
| **路径规划** | A*寻路/移动计算 |
| **AI协调** | AI调用决策/内容生成/结果处理 |
| **数据存储** | SQLite实时写入 / 状态恢复（无存档） |

### 2.3 后端详细职责清单

#### 2.3.1 数值计算（全部后端）

```
【能量系统】
├── 能量消耗计算：工作消耗 = -0.014/秒
├── 能量恢复计算：咖啡 +10，零食 +8~25，午餐 +40，睡眠 +50
├── 能量阈值检测：<50 触发零食购买，<10 强制睡眠
└── 能量惩罚计算：低于阈值时的效率惩罚

【专注力系统】
├── 专注力消耗计算：工作消耗 -0.017/秒
├── 专注力恢复计算：咖啡 +25，午餐 +25，小睡 +50
├── 专注力阈值检测：<60 触发咖啡机
└── 专注力惩罚计算：效率下降百分比

【社交需求系统】
├── 社交需求累积：独处 +0.028/秒
├── 社交需求恢复：打招呼 -15，闲聊 -40，午餐 -80，深度社交 -120
├── 社交需求惩罚：>50专注力-10%，>70效率下降
└── 强制社交触发：>100 强制社交

【情绪系统】
├── 情绪变化计算：工作 -0.003/秒，成功 +10~15，失败 -15~25
├── 情绪惩罚计算：社交需求>70时 -0.5/秒
├── 情绪恢复计算：社交 +5~25，睡眠 +10
└── 表情状态判定：基于情绪值返回对应表情

【睡意系统】
├── 睡意累积计算：清醒 +0.012/秒
├── 睡意恢复计算：小睡 -40，睡眠8小时 -100
└── 睡眠触发判定：≥90 强制睡眠

【竞争系统】
├── 竞争触发检测：同职业≥2空闲Agent
├── 抽签结果计算：Math.random等概率
├── 情绪影响计算：赢家 +8~15，输家 -5~10
├── 关系影响计算：输家与赢家关系 -3~-5
├── 加倍惩罚判定：失败/超时/评分<2
└── 加倍惩罚计算：情绪 -30~-50

【奖励系统】
├── XP计算：任务难度 × 完成质量
├── 积分计算：任务完成 +10~30，挑战 +100~500
├── 城主XP计算：完成任务 +10，协作 +25，危机 +50
└── 升级判定：XP达到 level × 100
```

#### 2.3.2 任务系统（全部后端）

```
【任务生成】
├── 任务复杂度分析（AI）：需要几人/什么职业
├── 协作需求判断（AI）：是否需要多Agent
├── 任务难度评估：1-5星
└── 任务奖励计算：XP/积分/城主XP

【任务分配】
├── Agent能力匹配（AI）：评估职业匹配度
├── 分配决策（AI）：选择最优Agent
├── 竞争处理：举手检测/抽签
└── 任务状态更新：pending → in_progress

【任务执行】
├── 进度计算：基于时间和难度
├── 完成判定：进度≥100% 或 超时
├── 完成质量评价（AI）：1-5分
└── 结果影响计算：成功/失败奖励惩罚

【协作任务】
├── 协作分配（AI）：各Agent角色
├── 协作效率计算：关系加成 +30%，职业互补 +20%
├── 协作成就感计算：完成 +15情绪
└── 协作失败处理：各自承担后果
```

#### 2.3.3 社交系统（全部后端）

```
【打招呼】
├── 触发检测：房间相遇 + 关系≥11 + 非竞争
├── 冷却检测：同一地点≥60分钟
├── 内容生成（AI）：基于性格/关系/场景
└── 效果计算：好感+1~3，关系+1，社交-15

【协作交流】
├── 对话内容生成（AI）：遇到问题时
├── 城主监听处理：AI生成内容推送前端
├── 本地模板显示：正常状态用模板
└── 效率加成计算：AI生成 +5%

【分享零食】
├── 分享判定（AI）：性格+关系+情境
├── 分享概率计算：30%（朋友）/60%（挚友）
├── 分享效果计算：分享者情绪+3，接受者+5
└── 接受者能量恢复：+5~15

【深度社交】
├── 时长判定：60-120分钟
├── 内容生成（AI）：有意义对话
├── 效果计算：社交-120，情绪+25
└── 关系提升计算：+5关系值

【社交需求惩罚】
├── 惩罚等级判定：>50/>60/>70/>85/>100
├── 专注力惩罚：-10%/-20%/-30%/-40%
├── 情绪惩罚：-5/-10/-20/-30 每小时
└── 强制社交触发：社交需求=100
```

#### 2.3.4 事件系统（全部后端）

```
【事件检测】
├── 触发条件检测：Token耗尽/连接中断/匹配度<20%
├── 随机事件生成：概率表随机选择
└── 周期性事件计时：小/中/大型挑战

【事件响应】
├── 响应策略生成（AI）：城主决策建议
├── 城主决策处理：接受/拒绝/调整
├── 事件效果计算：奖励或惩罚
└── 事件日志记录：存档用
```

#### 2.3.5 城主系统（全部后端）

```
【城主技能】
├── 技能效果计算：激励+30能量，灵感+15%质量
├── 冷却计时：精确到秒
├── 解锁判定：等级要求
└── 技能点消耗计算

【城主经验】
├── XP累计：完成任务/协作/危机
├── 等级判定：达到累计XP阈值
└── 解锁内容：技能/设施

【城主视角】
├── 所有状态推送：Agent/房间/任务
├── 城主可见提示：活动/竞争/事件
└── 城主操作处理：分配/干预/技能
```

## 四、前后端通信协议

### 4.1 WebSocket消息（后端→前端）

```typescript
// 后端推送的消息类型
type ServerMessage =
  | { type: 'state:init'; data: GameState }           // 初始化
  | { type: 'state:snapshot'; data: GameSnapshot }     // 完整快照

  | { type: 'task:update'; taskId: string; changes: Partial<TaskState> }  // 任务更新
  | { type: 'task:complete'; taskId: string; result: TaskResult }  // 任务完成
  | { type: 'social:greeting'; agentA: string; agentB: string; content: string }  // 打招呼
  | { type: 'social:collab'; agents: string[]; content: string }  // 协作对话
  | { type: 'social:share'; giver: string; receiver: string; item: string }  // 分享零食
  | { type: 'event:trigger'; event: GameEvent }  // 事件触发
  | { type: 'competition:start'; agents: string[] }  // 竞争开始
  | { type: 'competition:result'; winner: string; losers: string[] }  // 竞争结果
  | { type: 'skill:used'; skillId: string; target: string }  // 技能使用
  | { type: 'notification'; level: 'info'|'warn'|'error'; message: string }  // 通知
```

### 4.3 推送频率控制

```
【高优先级推送】（状态变化时立即推送）
├── Agent位置变化
├── 任务状态变化
├── 事件触发
└── 通知消息

【中优先级推送】（每秒或更慢）

【低优先级推送】（按需）

```

## 五、数据结构对比

### 5.1 后端完整状态

```python
# 后端：完整的游戏状态
class GameState:
    agents: Dict[str, AgentState]  # 包含所有属性和计算后的状态
    rooms: Dict[str, RoomState]
    tasks: Dict[str, TaskState]
    city_lord: CityLordState
    time: GameTime
    event_queue: List[GameEvent]

class AgentState:
    id: str
    name: str
    role: str
    position: Position           # {x, y, room_id}
    status: AgentStatus

    # 完整属性
    energy: float               # 0-100
    focus: float               # 0-100
    social_need: float         # 0-100
    mood: float                # 0-100
    sleepiness: float         # 0-100

    # 职业属性
    role_match: float          # 0-100
    xp: int
    level: int

    # 关系
    relationships: Dict[str, float]  # agent_id -> 关系值

    # 计算属性（每次tick重新计算）
    @property
    def efficiency(self) -> float: ...  # 基于能量/专注力/情绪/匹配度

    @property
    def current_emotion(self) -> str: ...  # 基于mood值

    @property
    def work_speed(self) -> float: ...  # 基于专注力/情绪

    # 冷却
    greeting_cooldowns: Dict[str, float]  # agent_id -> 剩余冷却秒数
```

## 七、禁止在前端做的业务逻辑

```
【绝对禁止】
❌ if (agent.energy < 50) { ... }    // 能量判断逻辑
❌ agent.mood += 10                   // 情绪修改
❌ calculateEfficiency(agent)         // 效率计算
❌ checkCompetition(agents)          // 竞争检测
❌ assignTask(task, agent)            // 任务分配
❌ generateGreetingContent(agent)     // 对话生成
❌ Math.random() > 0.5               // 概率判定
❌ 任何AI推理调用

【正确做法】
```

### 8.2 任务竞争流程

```
【后端处理】
GameServer.handleNewTask(task):
    # 1. AI分析任务复杂度
    analysis = await ai.analyze_task(task)
    
    # 2. 判断是否需要竞争
    if analysis.requires_single and has_multiple_idle_same_role(task.role):
        # 3. 检测举手
        candidates = get_idle_agents_by_role(task.role)
        
        # 4. 抽签
        winner = random.choice(candidates)
        losers = [a for a in candidates if a != winner]
        
        # 5. 计算影响
        for loser in losers:
            loser.mood -= random.randint(5, 10)
            loser.relationships[winner.id] -= random.randint(3, 5)
        
        winner.mood += random.randint(8, 15)
        
        # 6. 推送结果
        broadcast({
            type: 'competition:result',
            winner: winner.id,
            losers: [l.id for l in losers]
        })
        
        # 7. 分配任务
        task.assign_to(winner)
    
    else:
        # 正常分配
        agent = ai.select_best_agent(task, available_agents)
        task.assign_to(agent)
```
