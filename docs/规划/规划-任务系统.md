> **文档版本**：v1.0
> **关联文档**：`规划-游戏机制.md`

## 1. 任务概述

任务系统是Hermes数字工作室的核心玩法之一。主agent作为城主，通过分配任务给子Agent来推动游戏进展。

---

## 2. 任务类型

### 2.1 按职业分类

| 任务类型 | 适用职业 | 匹配度基准 |
|----------|----------|------------|
| 设计任务 | 设计师 | 90-100% |
| 编码任务 | 程序员 | 90-100% |
| 测试任务 | 测试员 | 90-100% |
| 分析任务 | 分析师 | 90-100% |

### 2.2 按规模分类

| 类型 | 难度 | 基础积分 | 基础XP | 完成时间 |
|------|------|----------|--------|----------|
| 简单任务 | ★ | 10-15 | 20 | 1-3秒 |
| 普通任务 | ★★ | 20-30 | 50 | 5-10秒 |
| 困难任务 | ★★★ | 40-50 | 100 | 15-30秒 |
| 史诗任务 | ★★★★ | 80-100 | 200 | 60+秒 |

### 2.3 按性质分类

| 类型 | 说明 | 可协作 |
|------|------|--------|
| 个人任务 | 单Agent独立完成 | 否 |
| 协作任务 | 需要多个Agent配合 | 是 |
| 子任务 | 从主任务拆分 | 否 |
| 灵感任务 | 交流中产生的新想法 | 可能 |

---

## 3. 任务生成

### 3.1 自动生成

| 来源 | 频率 | 说明 |
|------|------|------|
| 系统生成 | 每日 | 自动生成当日待办任务 |
| 协作触发 | 不定期 | Agent交流产生新任务 |
| 挑战触发 | 周期性 | 大挑战拆分出的任务 |

### 3.2 任务池

```
任务池 (TaskPool)
├── pending[]      // 待领取
├── inProgress[]   // 进行中
├── completed[]    // 已完成
└── failed[]      // 已失败
```

### 3.3 任务生成规则

- 每日8:00自动生成当日任务（3-5个）
- 任务池上限：10个待领取任务
- 超过上限时不再自动生成

---

## 4. 任务分配

### 4.1 分配流程

```
主agent选择任务 → 主agent选择Agent → 系统判断匹配度 → 分配/拒绝
```

### 4.2 匹配度判定

| 匹配度 | 分配结果 | 效果 |
|--------|----------|------|
| ≥60% | 允许分配 | 正常效率 |
| 20-59% | 允许分配 | 效率下降，匹配度持续下降 |
| <20% | 拒绝分配 | 提示主agent重新选择 |

### 4.3 分配限制

- 每个Agent同时最多持有2个任务
- 同一任务不能分配给多个Agent
- 休息室中的Agent不能分配任务

---

## 5. 任务执行

### 5.1 执行状态

| 状态 | 说明 | 可中断 |
|------|------|--------|
| pending | 待开始 | 是 |
| in_progress | 执行中 | 是 |
| paused | 暂停 | - |
| completed | 已完成 | - |
| failed | 失败 | - |

### 5.2 执行消耗

| 消耗项 | 数值 | 说明 |
|--------|------|------|
| 饱食度 | **-0.5/秒** | 工作消耗 |
| Token配额 | -10/次 | 通信消耗（不是/秒） |
| 社交需求 | **+0.3/秒** | 工作时孤独感累积 |

### 5.3 进度计算

```
进度 += 基础速度 × 匹配度修正 × 情绪修正 × 技能加成
```

| 修正项 | 公式 |
|--------|------|
| 匹配度修正 | 匹配度 < 60% 时 = 匹配度 / 60 |
| 情绪修正 | 兴奋+20%, 积极+10%, 低落-10%, 焦躁-20% |
| 技能加成 | 效率型技能每级+10% |

---

## 6. 任务完成

### 6.1 完成判定

- 进度达到100%时任务完成
- **层层汇报流程**：
  1. 先向干系Agent交流（相关参与任务的Agent）
  2. 再向上级Agent汇报
  3. 逐级汇报至主agent
- 无法跳过汇报流程

### 6.2 完成奖励

| 奖励项 | 计算公式 |
|--------|----------|
| 积分 | 基础积分 × 匹配度等级系数 |
| XP | 基础XP × 质量系数 |
| 城主XP | 固定+10 |
| 情绪值 | +10 |
| 社交需求 | -10 |

### 6.3 质量系数

| 匹配度 | 质量系数 |
|--------|----------|
| 90-100% | 1.2 (优秀) |
| 60-89% | 1.0 (正常) |
| 20-59% | 0.8 (一般) |
| <20% | 0.5 (较差) |

## 7. 协作任务

### 7.1 触发条件

- 多个相关Agent同时接受同一任务
- 由主agent主动发起协作
- 或Agent自主交流触发

### 7.2 协作加成

| 加成条件 | 效果 |
|----------|------|
| 双Agent协作 | 效率+30%，总Token消耗-20% |
| 关系度≥80% | 额外效率+15% |
| 职业互补 | 额外质量+20% |

### 7.3 协作任务流程

```
创建协作任务 → 分配主Agent → 分配辅助Agent → 协作执行 → 协作完成
```

## 8. 任务竞争机制

### 8.1 触发条件

主agent通过AI推理判定任务只需某职业1人，但该职业有≥2个空闲Agent同时"举手"竞争。

### 8.2 竞争方式

纯随机抽签（每个举手Agent等概率中签，**不加权**，保持公平）。

### 8.3 竞争过程可见性

- 主agent端：显示"【竞争】{职业}{AgentA}和{AgentB}同时举手，随机抽签中…"，抽签结果弹出提示
- 赢家：头顶显示 🎉 胜利表情 + "我来！"气泡（持续3秒）
- 输家：头顶显示 😔 失落表情 + "下次再…"气泡（持续3秒）

### 8.4 竞争结果与影响

| 结果 | 情绪影响 | 关系影响 |
|------|----------|----------|
| 抢到任务（赢家） | +5~15（成就感） | — |
| 没抢到（输家） | -3~-8（失落） | 与赢家关系 -2~-5（嫉妒） |

### 8.5 加倍惩罚

抢到任务的Agent若触发以下任一情况，情绪**加倍扣除**（-10~-30）：

| 判定条件 | 说明 |
|----------|------|
| A. 任务失败 | TaskStatus = 'failed' |
| B. 进度不达标 | 任务超时未完成 |
| C. 主agent评价不满意 | 城主手动评分不通过 |

## 9. 任务数据结构

```typescript
interface Task {
  id: string;
  name: string;
  description: string;
  type: 'design' | 'code' | 'test' | 'analyze';
  difficulty: 1 | 2 | 3 | 4;
  
  // 状态
  status: 'pending' | 'in_progress' | 'paused' | 'completed' | 'failed';
  progress: number;  // 0-100
  
  // 分配
  assigneeId?: string;       // 主Agent
  collaboratorIds?: string[]; // 协作Agent
  
  // 数值
  baseScore: number;         // 基础积分
  baseXP: number;            // 基础XP
  estimatedTime: number;      // 预计秒数
  
  // 时间戳
  createdAt: number;
  startedAt?: number;
  completedAt?: number;
}
```
