# 崽崽数字小屋 — 产品需求规格说明书

> **文档版本**：v1.0
> **项目名称**：崽崽数字小屋 UI 改造
> **项目类型**：前端改造 + 游戏化机制
> **规划版本**：v2.5（2025-04-30）
> **状态**：待开发

---

## 1. 项目概述

### 1.1 项目背景

崽崽数字小屋是一个基于 Hermes Agent 的 AI 助手界面。当前界面为现代卡片式 UI，用户希望将其改造成具有 Rimworld 风格的模拟经营游戏界面，并增加多 Agent 养成经营机制。崽崽担任城主角色，管理一群子 Agent，通过任务分配、团队协作、设施升级等机制，体验模拟经营游戏的乐趣。

### 1.2 项目目标

将数字小屋改造成 **Rimworld 风格 + 多 Agent 养成经营**的全新界面。

### 1.3 项目范围

| 范围 | 说明 |
|------|------|
| 前端改造 | Rimworld 风格 UI（暖棕配色、像素字体、房间布局） |
| 游戏机制 | 14 个核心游戏机制 + 周目标系统 |
| 后端联动 | 与 Hermes 后端 Agent 系统对接 |
| 5 种房间 | 办公室×9、休息室、会议室、机房、资料室 |

## 4. 核心机制详细规格

### 4.1 Agent 需求系统

**功能说明**：Agent 有三个维度的需求，需要通过休息室活动恢复。

| 需求属性 | 初始值 | 下限 | 上限 | 降至0的影响 | 恢复方式 |
|----------|--------|------|------|-------------|----------|
| 饱食度(energy) | 100 | 0 | 100 | 工作效率-50% | 休息室交流 |
| 电量(quota) | 100 | 0 | 100 | 无法工作 | 休息室恢复 |
| 社交需求(socialNeed) | 50 | 0 | 100 | 工作质量下降，汇报变差 | 休息室互动 |

**数据模型**：
```typescript
energy: number;      // 饱食度 0-100
quota: number;       // Token配额 0-100
socialNeed: number;   // 社交需求 0-100
```

---

### 4.2 职业匹配度系统

**功能说明**：任务类型与 Agent 职业匹配度影响工作效率和产出质量。

| 匹配等级 | 匹配度范围 | 效率修正 | 质量修正 | 特殊效果 |
|----------|------------|----------|----------|----------|
| 完全匹配 | 90-100% | +30% | +20% | 无 |
| 基本匹配 | 60-89% | ±0% | ±0% | 无 |
| 不匹配 | 20-59% | -30% | -20% | 匹配度持续下降 |
| 严重不匹配 | <20% | -60% | — | **触发消极怠工** |

**消极怠工（slacking）表现**：
- 状态显示 😤 表情
- 移动速度变为 1格/4秒（正常为 1格/2秒）
- 汇报质量明显下降
- 连续不匹配会导致匹配度继续下降，甚至拒绝工作

**崽崽应对策略**：
- 分配匹配任务恢复匹配度
- 主动发起休息室社交活动
- 升级设施加速恢复

---

### 4.3 Agent 成长系统

**功能说明**：完成任务获得 XP，升级解锁技能点，可点亮技能树。

| 技能路线 | 技能点效果 |
|----------|-----------|
| ⚡ 效率型 | 任务速度 +10% / +20% / +30% |
| 🎯 精准型 | 输出质量 +10% / +20% / +30% |
| 💬 社交型 | 汇报表现更好，崽崽好感度+ |

**升级公式**：
```
升级所需XP = level * 100
例：Lv1→Lv2 需要 200 XP
```

**功能说明**：崽崽作为城主，管理设施升级和积分系统。

#### 4.4.1 城主积分

|----------|------|
| 完成普通任务 | +10~30 |

#### 4.4.2 设施升级

| 升级项 | 效果 | 消耗积分 |
|--------|------|----------|

### 4.5 事件系统

**功能说明**：右上角活动提示区随机出现事件，崽崽需要做出决策。

#### 4.5.1 突发挑战

| 事件 | 触发条件 | 崽崽应对 |
|------|----------|----------|
| Token配额耗尽 | Agent电量归零 | 切换备用模型或等待恢复 |
| ComfyUI连接中断 | 服务不可用 | 手动恢复服务 |
| 连续低质量输出 | 3次失败 | 沟通调整 |
| 职业匹配度<20% | 消极怠工 | 重新分配任务 |

#### 4.5.2 机会事件

| 事件 | 效果 | 崽崽选择 |
|------|------|----------|
| 额外任务包 | 双倍XP+积分 | 接受/拒绝 |
| 模型升级可用 | 性能提升 | 决定是否切换 |
| Agent协作机会 | A+B配合双倍积分 | 决定是否协作 |

### 4.6 Agent 关系系统

**功能说明**：类似动森/模拟人生，崽崽观察 Agent 间关系变化。

| 关系度 | 状态 | 效果 |
|--------|------|------|
| 80%+ | 🤝 挚友 | 协作效率+30% |
| 50-79% | 👍 友好 | 正常配合 |

| <20% | 😤 冲突 | 任务出错率增加，需崽崽调解 |

**关系提升方式**：休息室互动

### 4.7 Agent 自主交流系统

**功能说明**：Agent 之间可以"自由恋爱"——自发交流、碰撞想法，无需崽崽实时干预。

#### 4.7.1 触发条件

| 触发方式 | 说明 |
|----------|------|
| 空闲触发 | Agent空闲时，有概率自发找相邻Agent交流 |
| 话题触发 | 某个Agent的工作内容可能引起相邻Agent兴趣 |
| 关系触发 | 关系度≥50%时，交流概率大幅提升 |

#### 4.7.2 交流类型

| 类型 | Token消耗 | 效果 |
|------|-----------|------|
| 💬 闲聊 | 极低 | 关系度+，社交需求-，可能产生想法火花 |
| 💡 想法碰撞 | 低-中 | 可能触发新任务（子任务/协作任务） |
| 🤝 协作请求 | 中 | 直接触发协作任务，效率+ |
| ❓ 请教问题 | 低 | 触发答疑，提问方获得信息，解答方社交+ |

#### 4.7.3 Token消耗管控

| 管控项 | 说明 |
|--------|------|
| 全局开关 | 城主可开启/关闭Agent自主交流 |
| 单次上限 | 每个交流轮次Token上限（如200 tokens） |
| 每日上限 | 每Agent每日自主交流Token配额 |
| 崽崽可观察 | 交流内容在活动提示区显示，崽崽可随时介入 |

#### 4.7.4 协作效率加成

| 加成条件 | 效果 |
|----------|------|
| 双Agent协作 | 效率+30%，总Token消耗-20% |
| 关系度≥80% | 额外效率+15% |
| 职业互补（如设计+开发） | 额外质量+20% |

#### 4.7.5 任务触发

| 任务类型 | 说明 |
|----------|------|
| 🤱 子任务 | 从主任务拆分出的子任务 |
| 🔗 协作任务 | 需要多Agent配合完成的任务 |
| 💡 灵感任务 | 交流中产生的全新想法任务 |

### 4.8 Agent 情绪感染系统

**功能说明**：Agent的情绪会互相传染，形成"氛围场"。

#### 4.8.1 情绪类型

| 情绪 | 表情 | 效果 |
|------|------|------|
| 兴奋 | 😄 | 效率+20% |
| 积极 | 😊 | 效率+10% |
| 平静 | 😐 | 无加成（基准状态） |
| 低落 | 😔 | 效率-10% |
| 焦躁 | 😤 | 效率-20%，易出错，社交需求+ |

#### 4.8.2 情绪传染规则

| 传染场景 | 传染强度 | 效果 |
|----------|----------|------|
| 同房间Agent | 80% | 情绪同步化 |
| 相邻房间 | 50% | 部分影响 |
| 休息室社交 | 100% | 完全同步 |

#### 4.8.3 情绪病毒机制

- 一个Agent情绪极差（低落/焦躁）可能"传染"给周围Agent
- 连续3个Agent情绪低落 → 触发"团队士气危机"事件
- 崽崽可使用"激励演说"技能恢复团队情绪

#### 4.8.4 情绪恢复

| 方式 | 恢复效果 |
|------|----------|
| 休息室交流 | +20~40 情绪值 |
| 完成任务 | +10 情绪值 |
| 崽崽激励 | +30 情绪值 |
| 协作成功 | +15 情绪值 |

| 手动触发 | 崽崽点击"召开庆功宴" |

#### 4.13.2 庆功流程

## 5. Agent 数据模型

### 5.1 Agent 接口

```typescript
interface Agent {
  id: string;
  name: string;
  role: string;        // "设计师" / "程序员" / "测试员" / "分析师"
  isMain: boolean;

  // 身份与个性
  soulMdPath: string;
  soulMdContent: string;
  personality: string;

  // 形象
  avatarUrl: string;
  pixelArtUrl: string;

  // 模型配置
  modelProvider: string;
  modelName: string;
  modelConfig: { temperature?: number; maxTokens?: number; topP?: number; };

  // 房间与状态
  color: string;
  status: 'idle' | 'walking' | 'working' | 'reporting' | 'social' | 'chatting' | 'collaborating' | 'slacking' | 'error' | 'offline';
  room: number | 'rest' | 'server' | 'archive' | 'meeting' | 'home';
  homeRoom: number | 'home';
  currentTask?: Task;

  // 养成属性
  xp: number;
  level: number;
  skillPoints: number;
  skills: { efficiency: number; quality: number; social: number; };

  // 需求状态 (0-100)
  energy: number;      // 饱食度
  quota: number;       // Token配额
  socialNeed: number;  // 社交需求

  // 职业匹配度 (0-100)
  roleMatch: number;   // 当前任务与Agent角色的匹配度
  // <20%: 消极怠工(slacking), 效率-60%, 移动变慢, 汇报敷衍

  // 关系
  relationships: Record<string, number>;  // agentId -> 关系度

  // 自主交流
  dailyTokenQuota: number;       // 每日自主交流Token配额
  dailyTokenUsed: number;        // 今日已用Token
  isAutoChatEnabled: boolean;     // 是否开启自主交流

  // 协作
  collaborationCount: number;    // 累计协作次数
  lastCollaborationPartner?: string;  // 上次协作的AgentId

  // 情绪
  mood: 'excited' | 'positive' | 'neutral' | 'sad' | 'anxious';
  moodValue: number;  // 情绪值 0-100

  // 工作属性
  workMorale: number;  // 工作积极性 0-100
  confidence: number;  // 信心值 0-100

  modelUsage: ModelUsage[];
  sessionId: string;
  summary: string;
}
```

```typescript
interface CityLord {

```

| 消极怠工 | 因匹配度过低导致的低效状态 |
| 城主XP | 崽崽升级所需的经验值 |
| 城主技能 | 崽崽可主动释放的技能 |
